# AI Document Assistant

An AI-powered document question-answering application built with Python and FastAPI. Upload a PDF, ask questions about its content, and receive natural-language answers generated by a local large language model (LLM).

The application uses **Retrieval-Augmented Generation (RAG)** to retrieve relevant document chunks using semantic search and generate answers using Gemma through Ollama.

## Features

- Upload PDF documents through a REST API.
- Extract text from PDFs using PyMuPDF.
- Split extracted text into smaller, overlapping chunks.
- Generate text embeddings using `nomic-embed-text`.
- Perform semantic search using cosine similarity.
- Retrieve the most relevant chunks for a user's question.
- Apply a similarity threshold to filter potentially irrelevant questions.
- Generate natural-language answers using Gemma 2B through Ollama.
- Return source text and similarity scores with answers.
- Validate request data using Pydantic.
- Handle invalid PDFs and missing documents.
- Explore and test API endpoints using Swagger UI.

## How It Works

The application follows a basic RAG pipeline:

1. Upload a PDF document through the API.
2. Extract text from the PDF using PyMuPDF.
3. Split the extracted text into overlapping chunks.
4. Generate an embedding for each chunk using `nomic-embed-text`.
5. Store the chunks and their embeddings in memory.
6. Submit a question about the document.
7. Generate an embedding for the question.
8. Calculate cosine similarity between the question embedding and each document chunk embedding.
9. Rank the chunks and retrieve the three highest-scoring chunks.
10. Check the highest similarity score against a relevance threshold.
11. Send the retrieved context and question to Gemma through Ollama.
12. Return the generated answer, source chunks, and similarity scores as a JSON response.

## Installation and Setup

### 1. Clone the Repository

```bash
git clone https://github.com/uday-Tharlada-0/AI_DOCUMENT_ASSISTANT.git
cd AI_DOCUMENT_ASSISTANT
```

### 2. Install Dependencies

Install the project's dependencies using `uv`:

```bash
uv sync
```

### 3. Download the Required Models

Download Gemma:

```bash
ollama pull gemma:2b
```

Download the embedding model:

```bash
ollama pull nomic-embed-text
```

Verify the installed models:

```bash
ollama list
```

### 4. Configure Ollama

Ensure the Ollama server is running and accessible from the environment where the FastAPI application runs.

The application uses two Ollama API endpoints.

**Text generation:**

```text
http://<ollama-host>:11434/api/generate
```

**Text embeddings:**

```text
http://<ollama-host>:11434/api/embed
```

Replace `<ollama-host>` with the appropriate hostname or IP address for your environment.

The application supports configuring the endpoints through environment variables:

```bash
export OLLAMA_URL="http://<ollama-host>:11434/api/generate"
export OLLAMA_EMBED_URL="http://<ollama-host>:11434/api/embed"
```

These are Linux/macOS shell examples. Configure the equivalent environment variables in your operating system if necessary.

If the FastAPI application runs inside WSL while Ollama runs on Windows, use the Windows host address accessible from WSL.

Keep the Ollama server accessible only to trusted systems. Avoid exposing the Ollama API directly to the public internet.

### 5. Start the FastAPI Application

If `main.py` is in the project root, run:

```bash
uv run uvicorn main:app --reload
```

If your application uses a `src/` directory, use the import path appropriate for your package structure.

### 6. Open Swagger UI

Once the application starts, open:

http://127.0.0.1:8000/docs

Use the interactive API documentation to upload a PDF and ask questions about its content.

## API Endpoints

| Method | Endpoint | Description |
|---|---|---|
| GET | `/` | Check whether the application is running |
| POST | `/upload` | Upload a PDF, extract its text, create chunks, and generate embeddings |
| POST | `/ask` | Retrieve relevant chunks and generate an answer |

### Upload a PDF

**Endpoint:** `POST /upload`

Upload a PDF through Swagger UI using the file upload field.

The application extracts the document text, divides it into chunks, and generates an embedding for each chunk.

Example response:

```json
{
  "filename": "Python and Java Study Notes.pdf",
  "pages": 10,
  "message": "File uploaded and text extracted successfully."
}
```

The filename and page count above are illustrative.

### Ask a Question

**Endpoint:** `POST /ask`

Example request:

```json
{
  "filename": "Python and Java Study Notes.pdf",
  "question": "Explain high-level programming languages."
}
```

The filename must match a document uploaded to the running application.

Example response:

```json
{
  "question": "Explain high-level programming languages.",
  "answer": "A high-level programming language provides abstractions that make programming easier to understand and write.",
  "sources": [
    {
      "similarity": 0.7821,
      "text": "A high-level programming language is designed to make programs easier to write and understand..."
    }
  ]
}
```

The answer, source text, and similarity score above are illustrative. Actual results depend on the PDF, retrieved chunks, embedding model, and language model.

### Understanding Similarity Scores

Cosine similarity measures the relationship between the question embedding and a document chunk embedding.

The application ranks chunks by their similarity scores and selects the highest-scoring chunks.

A relevance threshold is used to reject questions when the best-scoring chunk falls below the configured value.

**Important:** Similarity scores are not percentages or guarantees of relevance. The threshold must be evaluated against representative questions and documents.

## Current Limitations

- Uploaded documents and embeddings are stored in memory and are lost when the application restarts.
- Documents must be uploaded again after a restart.
- The application currently uses fixed-size chunking, which can split sentences or words.
- Retrieval quality depends on the embedding model, chunking strategy, and document content.
- A similarity threshold cannot guarantee that a question is relevant to the document.
- The language model may generate unsupported information despite instructions to use the supplied context.
- Scanned PDFs without extractable text may require OCR.
- Authentication and persistent document storage have not yet been implemented.
- The application does not yet provide a dedicated frontend.
- Ollama must be reachable from the environment running FastAPI.
